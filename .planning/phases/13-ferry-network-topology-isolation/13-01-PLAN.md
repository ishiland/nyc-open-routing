<objective>
Isolate ferry route internal nodes from bridge/tunnel nodes in the pgRouting topology so the routing engine cannot jump between ferry and bridge/tunnel edges mid-crossing.

Purpose: LION ferry segments share 2D endpoint coordinates with bridge/tunnel segments despite being at different elevations (water level vs. elevated). pgr_extractVertices assigns them the same vertex IDs, allowing invalid route transitions. This SQL fix creates new vertex IDs for ferry internal nodes while preserving terminal connectivity to the street network.

Output: Modified `09_ferry_connections.sql` that first isolates ferry internal nodes from bridge/tunnel topology, then creates SI Ferry manual connections as before.
</objective>

**New Step 0: Isolate Ferry Internal Nodes from Bridge/Tunnel Topology**

The SQL must perform these operations in order:

1. **Identify ferry nodes** — collect all node IDs that are source or target of any edge with `featuretyp = 'F'`:
   ```sql
   -- CTE: ferry_nodes
   SELECT DISTINCT node_id FROM (
       SELECT source AS node_id FROM edges WHERE featuretyp = 'F'
       UNION
       SELECT target AS node_id FROM edges WHERE featuretyp = 'F'
   ) sub
   ```

2. **Classify each ferry node as terminal or internal** — a node is "terminal" (should stay shared) if it connects to at least one edge that is NOT a ferry AND is NOT a bridge (`rw_type='3'`) AND is NOT a tunnel (`rw_type='4'`). A node is "internal" (must be isolated) if every non-ferry edge connected to it is a bridge or tunnel:
   ```sql
   -- CTE: node_classification
   SELECT fn.node_id,
       bool_or(e.featuretyp != 'F' AND e.rw_type NOT IN ('3', '4')) AS has_street_connection
   FROM ferry_nodes fn
   JOIN edges e ON (e.source = fn.node_id OR e.target = fn.node_id)
   GROUP BY fn.node_id
   ```
   Internal nodes: `has_street_connection = FALSE`

3. **Filter to only nodes actually shared with bridge/tunnel edges** — internal nodes that also appear as source/target of bridge or tunnel edges (rw_type IN ('3','4')). Skip any internal node that is only connected to other ferry edges (ferry-only nodes are already isolated):
   ```sql
   -- CTE: shared_internal_nodes
   -- Must be an internal ferry node AND connected to at least one bridge/tunnel edge
   SELECT nc.node_id FROM node_classification nc
   WHERE nc.has_street_connection = FALSE
   AND EXISTS (
       SELECT 1 FROM edges e
       WHERE (e.source = nc.node_id OR e.target = nc.node_id)
       AND e.rw_type IN ('3', '4')
   )
   ```

4. **Create new vertex IDs** — use `COALESCE(MAX(id), 0) + ROW_NUMBER() OVER ()` to generate unique IDs:
   ```sql
   -- Temp table: ferry_node_mapping (old_id, new_id)
   CREATE TEMP TABLE ferry_node_mapping AS
   SELECT
       node_id AS old_id,
       (SELECT COALESCE(MAX(id), 0) FROM edges_vertices_pgr) + ROW_NUMBER() OVER (ORDER BY node_id) AS new_id
   FROM shared_internal_nodes;
   ```

5. **Insert new vertices** into `edges_vertices_pgr` at the same geometry as the old nodes:
   ```sql
   INSERT INTO edges_vertices_pgr (id, geom, x, y)
   SELECT m.new_id, v.geom, v.x, v.y
   FROM ferry_node_mapping m
   JOIN edges_vertices_pgr v ON v.id = m.old_id;
   ```

6. **Update ferry edges** — change source/target on ferry edges (`featuretyp = 'F'`) to point to new vertex IDs. Two separate UPDATE statements (one for source, one for target):
   ```sql
   UPDATE edges e SET source = m.new_id
   FROM ferry_node_mapping m
   WHERE e.featuretyp = 'F' AND e.source = m.old_id;

   UPDATE edges e SET target = m.new_id
   FROM ferry_node_mapping m
   WHERE e.featuretyp = 'F' AND e.target = m.old_id;
   ```

   - Number of internal nodes isolated

   - Number of terminal nodes preserved (not isolated)

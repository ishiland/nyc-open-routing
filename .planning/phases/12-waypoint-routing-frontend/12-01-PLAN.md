- `removeWaypoint: (index: number) => void`

- `clearWaypoints: () => void`
- `setWaypointRoute: (route: WaypointRouteResponse | null) => void`

- Add `useState<IMapFeature[]>([])` for waypoints
- Add `useState<WaypointRouteResponse | null>(null)` for waypointRoute
- Add `addWaypoint` callback: `setWaypoints(prev => [...prev, waypoint])` — limit to 1 intermediate waypoint (check `prev.length < 1` per backend constraint, show warning if at limit)
- Add `removeWaypoint` callback: `setWaypoints(prev => prev.filter((_, i) => i !== index))`
- Add `updateWaypoint` callback: `setWaypoints(prev => prev.map((wp, i) => i === index ? waypoint : wp))` — replaces waypoint at given index (used by WaypointSearch when user selects an address)

**3. Create useWaypointRouteFetch hook:**

Create `client/src/hooks/useWaypointRouteFetch.ts` following the same pattern as `useRouteFetch.ts`:

```typescript
import { useCallback, useState } from "react"
import { Point } from "geojson"
import { IMapFeature, WaypointRouteResponse } from "../types/interfaces"
import { TravelMode } from "../contexts/RoutingContext"
import { MessageContextType } from "../contexts/MessageContext"

interface UseWaypointRouteFetchArgs {
  startAddress: IMapFeature | null
  endAddress: IMapFeature | null
  waypoints: IMapFeature[]
  mode: TravelMode
  useTraffic: boolean
  avoidFerries: boolean
  trafficHour: number | null
  trafficDayOfWeek: number | null
  setWaypointRoute: (route: WaypointRouteResponse | null) => void
  setRoute: (route: null) => void  // To clear regular route when using waypoints
  setSelectedStreet: (street: null) => void
  displayMessage: MessageContextType["displayMessage"]
}
```

The hook should:
- Build pipe-delimited waypoints URL: `startCoords|wp1Coords|...|endCoords`
- Construct URL: `/api/route/waypoints?waypoints=${waypointsParam}&mode=${mode}` with traffic/ferry params matching useRouteFetch pattern
- Include 30-second AbortController timeout (same as useRouteFetch)
- On success: call `setWaypointRoute(data)` and `setRoute(null)` (clear regular route)
- On error: `setWaypointRoute(null)`, then display user-friendly messages (404 = "No route found", 500 = server error, abort = timeout, same pattern as useRouteFetch)
- Validate: startAddress, endAddress, and waypoints.length > 0 must all be present
- Return `{ fetchWaypointRoute, isFetchingWaypoints }`

<task type="auto">
  <name>Task 1: Add isInitialized guard to useRouteStateSync</name>
  <files>client/src/hooks/useRouteStateSync.ts</files>
  <action>
    The race condition: Two useEffects run on mount. The first (init) reads URL params and calls setMode("bike"). The second (URL update) runs with the current state values which still reflect the default "drive" (because React hasn't re-rendered yet), and writes `?mode=drive` to the URL, overwriting the user's intended mode.

    Fix:
    1. Import `useRef` from React (add to existing import).
    2. Create `const isInitialized = useRef(false)` at the top of the hook, before any effects.
    3. In the first useEffect (the mount-only init effect, the one with `[]` deps):
       - After all the param restoration logic (after the endParam block), add:
         ```
         queueMicrotask(() => {
           isInitialized.current = true
         })
         ```
       - Using queueMicrotask ensures the flag is set after React processes the state batch from all the set* calls in the init effect, but before the next effect cycle.
    4. In the second useEffect (the URL update effect, the one with `[startAddress, endAddress, mode, ...]` deps):
       - Add an early return guard at the very top: `if (!isInitialized.current) return`
       - This prevents the URL update effect from firing during the initial mount render when state still has default values.

    Do NOT change any other logic in either effect. Do NOT remove the eslint-disable comment on the init effect. Do NOT change the dependency arrays.
  </action>
  <verify>

    Manual check: Open `/?mode=bike&start=-74.006,40.7128&startAddr=Test&end=-73.935,40.7306&endAddr=Test2` — mode should be "bike" not "drive".
  </verify>
  <done>The URL update effect no longer fires before initialization is complete. Deep links correctly preserve the mode parameter. Existing URL sync behavior unchanged after init.</done>

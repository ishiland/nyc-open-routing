**Function 1: `getdrivingisochrone_edges`**

Signature: `(lon FLOAT, lat FLOAT, intervals FLOAT[], use_traffic BOOLEAN DEFAULT FALSE, hour INT DEFAULT NULL, day_of_week INT DEFAULT NULL)`

Returns: `TABLE(edge_id INT, band_index INT, agg_cost FLOAT, street TEXT, geom GEOMETRY)`

Logic — copy the existing `getdrivingisochrone` function's DECLARE block and traffic/edges_sql construction EXACTLY (same bbox_buffer of 1500, same traffic factor lookup, same dynamic traffic logic). The only change is the final RETURN QUERY:

Replace the `reachable_nodes` CTE with `reachable_edges`:
```sql
reachable_edges AS (
    SELECT dd.edge AS eid, dd.agg_cost
    FROM pgr_drivingDistance(edges_sql, start_node, max_cost, TRUE) dd
    WHERE dd.edge != -1
),
```

Replace the `node_geoms` CTE with `edge_geoms`:
```sql
edge_geoms AS (
    SELECT DISTINCT ON (re.eid)
        re.eid,
        re.agg_cost,
        e.street,
        ST_Transform(ST_SimplifyPreserveTopology(e.the_geom, 0.0001), 4326) AS the_geom
    FROM reachable_edges re
    JOIN edges e ON e.id = re.eid
),
```

IMPORTANT: Use `DISTINCT ON (re.eid)` because `pgr_drivingDistance` can return the same edge multiple times (traversed from different directions). Take the first occurrence (lowest agg_cost due to ordering inherent in the algorithm).

Replace the final SELECT with:
```sql
SELECT
    eg.eid::INT AS edge_id,
    i.idx::INT AS band_index,
    eg.agg_cost::FLOAT AS agg_cost,
    eg.street::TEXT AS street,
    eg.the_geom AS geom
FROM intervals i
JOIN edge_geoms eg ON eg.agg_cost <= i.val
    AND (i.idx = 1 OR eg.agg_cost > COALESCE(
        (SELECT val FROM intervals WHERE idx = i.idx - 1), 0
    ))
ORDER BY i.idx, eg.agg_cost;
```

Key difference from polygon version: Each edge appears in exactly ONE band (the tightest band that contains it), not in all bands up to its cost. This is done via the `AND (i.idx = 1 OR eg.agg_cost > prev_interval)` condition. This prevents duplicate edges across bands and makes client rendering straightforward — each edge has a single band_index.

**Function 3: `getwalkingisochrone_edges`**

Signature: `(lon FLOAT, lat FLOAT, intervals FLOAT[])`

Returns: Same return type.

Same pattern as biking but:
- Use `getnearestwalknode` for snapping
- bbox_buffer: `GREATEST(max_cost * 150, 5000)` (same as existing walk iso)
- edges_sql: `cost_walk AS cost, rcost_walk AS reverse_cost FROM edges WHERE walkable = TRUE`
- `pgr_drivingDistance(edges_sql, start_node, max_cost, FALSE)` — **FALSE for undirected** (pedestrians walk either direction, same as existing walk iso)

**Critical details:**
- `ST_SimplifyPreserveTopology(e.the_geom, 0.0001)` — tolerance in SRID 2263 units (feet), 0.0001 feet is sub-millimeter, effectively no simplification at DB level. This preserves geometry fidelity; simplification happens client-side if needed. Use this value because the research suggested it for SRID 4326 coordinates, but since `the_geom` is SRID 2263, use a small value that preserves shape. A reasonable value for SRID 2263 would be `1` (1 foot tolerance) to actually reduce coordinate count. Use `ST_SimplifyPreserveTopology(e.the_geom, 1)` instead — 1 foot tolerance removes sub-foot jitter while preserving street shape.
- `ST_Transform(..., 4326)` to convert from SRID 2263 to WGS84 for GeoJSON consumption
- Each DROP FUNCTION IF EXISTS before CREATE OR REPLACE, matching the existing pattern in the file
- Include the `street` column from the edges table (column name is `street`, NOT `streetname`)

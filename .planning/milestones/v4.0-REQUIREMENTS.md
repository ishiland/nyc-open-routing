# Requirements: NYC Open Routing

**Defined:** 2026-02-15
**Core Value:** The UI must feel like a native NYC tool — compact, bold, and immediately usable

## v4.0 Requirements

Requirements for live traffic data features. Each maps to roadmap phases.

### Live Traffic Refresh

- [x] **REFRESH-01**: TRANSCOM speed data auto-refreshes on a configurable interval (default 5 min) via background task in the API process
- [x] **REFRESH-02**: Traffic data updates are atomic — no inconsistency window where all edges reset to 1.0 during refresh
- [x] **REFRESH-03**: Background refresh handles failures gracefully — keeps existing data on error, logs failure, does not crash the API
- [x] **REFRESH-04**: Refresh uses incremental updates — only writes edges whose traffic_factor actually changed, avoiding unnecessary DB writes
- [x] **REFRESH-05**: Traffic status endpoint (`GET /api/traffic/status`) reports last refresh time, success/failure, and edge count
- [x] **REFRESH-06**: Manual refresh trigger via `POST /api/traffic/refresh` for development and debugging
- [x] **REFRESH-07**: Route cache is invalidated after each successful traffic data refresh

### Traffic Visualization

- [x] **VIZ-01**: Toggleable map layer colors street segments by traffic condition using green/yellow/orange/red scale matching existing route traffic colors
- [x] **VIZ-02**: Traffic layer toggle is independent of the routing TrafficToggle — users can see traffic while in any travel mode or with no route active
- [x] **VIZ-03**: Only edges with actual traffic data are rendered (traffic_factor > 1.0) — absent data shows no color, not green
- [x] **VIZ-04**: Traffic data loads viewport-bounded with bounding box filtering to keep payloads small
- [x] **VIZ-05**: Legend shows color-to-condition mapping when traffic layer is active
- [x] **VIZ-06**: Freshness indicator shows "Updated X min ago" near the traffic toggle, color-coded by data age

### Startup Configuration

- [x] **CONFIG-01**: Environment variable `TRAFFIC_ENABLED` (default: false) enables/disables live traffic refresh at startup
- [x] **CONFIG-02**: Environment variable `TRAFFIC_REFRESH_INTERVAL` controls refresh frequency (default: 5 min)
- [x] **CONFIG-03**: Startup traffic import runs in background — API serves requests immediately without waiting for traffic data
- [x] **CONFIG-04**: Startup logs report resolved traffic configuration values for debugging
- [x] **CONFIG-05**: Health endpoint reflects traffic data readiness (`traffic_data_loaded: true/false`)
- [x] **CONFIG-06**: Startup import retries on failure (max 3 attempts with backoff) instead of giving up

### Volume Data Audit

- [x] **AUDIT-01**: Coverage overlap analysis determines how many edges have data from each source (volume vs speed) and how many have both
- [x] **AUDIT-02**: SQL fallback chain priority documented and reordered: live speed factor -> static volume factor -> 1.0
- [x] **AUDIT-03**: Clear recommendation produced: keep, merge, or deprecate volume data based on coverage analysis
- [x] **AUDIT-04**: SQL routing functions updated to use combined fallback chain (live speed primary, volume gap-fill, 1.0 default)

## Future Requirements

- Bidirectional traffic display (line offset per direction) — HIGH complexity, defer
- Vector tile traffic layer — only if GeoJSON performance proves insufficient
- Hover tooltips on traffic segments — MEDIUM complexity, nice-to-have
- Zoom-dependent road class filtering — show highways at low zoom, local streets at high zoom
- Automatic periodic map layer refresh — re-fetch traffic data every 30-60s when layer visible
- Traffic on route segments with data source indicator (live/static/none styling)

## Out of Scope

| Feature | Reason |
|---------|--------|
| WebSocket push for traffic updates | Over-engineering for 5-min data cycle; HTTP polling sufficient |
| Separate worker container (Celery/Redis) | Single process scheduling sufficient for POC |
| Vector tile server (Martin/pg_tileserv) | Only ~3-5K edges with traffic data; GeoJSON handles this |
| Traffic on bike/walk modes | No sensor data exists for non-vehicle modes |
| Interpolating traffic to uncovered roads | Creates false information; show data only where it exists |
| Animated traffic flow direction | Novelty feature; doesn't add actionable information |
| Sub-minute refresh intervals | TRANSCOM data doesn't change faster than sensor reporting interval |
